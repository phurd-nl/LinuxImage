1 · Laptop

The tech plugs into the imaging VLAN, leaves power connected, and chooses UEFI PXE. Next is VLAN DHCP.

2 · VLAN DHCP

The offer is next server 192.168.26.106 and file snponly.efi. That file is what a Lenovo L15 can load. DHCP is not on the opsi host. Next is TFTP.

3 · TFTP

The opsi container listens on UDP 69 and serves snponly.efi. Next is default.ipxe.

4 · default.ipxe

Today this script enrolls the laptop and arms Windows. The next change is to chainload grub.x64.efi instead. If that file does not start, the text menu is next.

5 · grub.x64.efi

The graphical binary. The theme lives inside it. Next is grub.cfg. If the firmware refuses this file, next is the iPXE text menu, not the simple GRUB menu.

6 · grub.cfg

Tries 1280×720, then 1024×768, then auto. The menu waits for a key. Next on Esc, or when graphics fail, is grub-simple.cfg. Otherwise the tech picks a row 3 choice. A per-MAC file that waits 0 seconds must not open first.

Simple GRUB

Text only. Same choices as the picture. It is next when the font fails, when gfxterm refuses, and when the tech presses Esc on a black screen.

iPXE text

Plain type, same choices. It is next only when grub.x64.efi never starts. That is the L15 case until one L15 passes the chainload.

Local disk

GRUB chainloads the EFI already on the disk. The path stops. Nothing is enrolled.

7 · Windows 11

The choice that continues. Next is win11.ipxe on row 4. It must not return to default.ipxe.

Ubuntu 26.04

Shown on the menu and returns to row 3. The seed still has a plaintext password, the root volume has 4.8 GB free, and nothing is listening for the NoCloud files.

Sign in to image

The graphical menu opens this screen. The tech signs in once. Next is the Entra search, the NextDesk snapshot, and the split between software that installs now and software the endpoint queues for after the employee signs in.

Find the person

Search Entra by name or email and assign that account to this laptop. The employee does not sign in on this screen. The tech’s token is not their laptop login.

Old laptop

NextDesk holds the snapshot of their previous machine. The screen pulls that snapshot and lists the software that was on it. A person with no snapshot gets an empty list. The OS choice and Deploy still work.

Install now

From that list, software that makes sense before anyone logs in, and that matches a package the installer can lay down, goes into the selection file. Windows turns matching rows into opsi product actions. Ubuntu installs them from the same file during the image.

Queue the rest

Everything else from the snapshot is handed to the endpoint queue. It installs after the employee signs in. It does not run inside WinPE or the Ubuntu installer.

8 · win11.ipxe

A second iPXE file whose only job is the auto-enroll URL. Next is auto-enroll.

9 · Auto-enroll

Port 8080 creates NL-<serial>.lab.local and arms win11-x64 plus the client agent, identity, inventory, audits, Chrome bookmarks, and the start menu. Next is the boot image.

10 · Boot image

Kernel and initrd over HTTP. It partitions the disk and stages Windows. Next is opsiconfd.

11 · opsiconfd

4.3.53.10 on TCP 4447. Next is the win11-x64 product on the depot.

12 · win11-x64

The Windows product, about 8.6 GB. There is no Ubuntu product. The paid Linux agent is present and unused. Next is WinPE.

13 · WinPE

Unattended Windows Setup. Next is specialize, on the first boot into Windows.

14 · Specialize

DHCP, Wi-Fi, firewall, OOBE policy, and Entra join. NextAdmin is the local setup account. Next is postinst.d.

15 · postinst.d

Debloat, Atera, Wazuh, UniFi, core apps, OneDrive, the start menu, hide NextAdmin, and handoff. Next is the employee’s work sign-in.

16 · Work sign-in

The employee signs in with a work account. Inventory and bookmarks follow from the client agent. Next, after the image succeeds, is the new-hire group.

17 · New-hire group

Entra device settings allow only this security group to join a device. The name does not start with linux-, so authd does not make it a local group. The employee is added when the laptop is assigned. linux-sudo is a different group and is not involved.

18 · Device join

The employee signs in while they are still in the group. That sign-in joins the device. On Ubuntu this is the authd login that runs register_device. On Windows it is the Entra join. allowed_users = ALL and an empty owner mean this login does not lock the laptop to one person.

Ubuntu autoinstall

The desktop ISO boots with the NoCloud seed. Disk layout comes from the seed. The tech is not asked for a password. This step does not exist on the Windows path.

Encrypt /home

LUKS on the home volume, TPM seal, and a recovery slot. Windows imaging does not encrypt the disk in this plan. The employee’s later Entra password can be written to slot 0 only if they typed it.

authd

UbuntuOauth tenant and client id. allowed_users = ALL and an empty owner. No client secret on the laptop. The new-hire group is what allows the device join, and it is not named linux-.

Ubuntu install-now apps

The same selection file Windows uses. Packages that belong in the image install here: dock, Teams, Outlook, and the OneDrive package. The endpoint queue still holds the rest until after sign-in.

Ubuntu employee sign-in

They type user@domain and the Entra password. That password can open the disk slot. A QR login does not reveal it. This is their sign-in, not the tech’s.

Windows Entra join

The employee signs in while they are in the new-hire group. That is the Windows join. Removing them from the group a day later does not unjoin the device.

Ubuntu device register

The employee’s authd login runs register_device while they are in the new-hire group. allowed_users = ALL keeps the laptop from locking to one owner. A day later they leave the group and the registration stays.

19 · Leave the group

The membership ends 24 hours after the add. A daily job removes anyone older than a day if the assignment has no end time. The device stays joined. The person stays signed in. They cannot join another device.
