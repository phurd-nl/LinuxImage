Getting imaging back

What to do when laptops stop imaging, from the fastest undo to rebuilding the imaging host. Commands run on the opsi host (ssh opsi, then sudo -i) unless they say MikroTik. The bench steps are the imaging SOP; the map is the imaging topology.

Pick the right fix

What you seeDo this

Two places hold the boot setup: the MikroTik IT-Foghat-RTR (which file a laptop is told to boot) and the opsi VM (which serves it). The VM snapshot does not cover the MikroTik. Every rollback below says which side it touches.

1. Back to the old boot path

This is how imaging worked before 10 November: the MikroTik hands out snponly.efi (options 66/67), the opsi container serves it over TFTP, Secure Boot is off. Windows imaging works this way. Ubuntu with whole-disk encryption does not, because it needs Secure Boot on.

  1. MikroTik: put options 66/67 back. WinBox → New Terminal: 
    /ip dhcp-server network set 0 next-server=192.168.26.106 boot-file-name=snponly.efi
/ip dhcp-server option sets set opsi options=opsi-tftp,opsi-boot
/ip dhcp-server network print detail
/ip dhcp-server option sets print detail
    Row 0 (192.168.26.0/24) should show next-server=192.168.26.106 boot-file-name="snponly.efi", and set opsi should list opsi-tftp,opsi-boot.
  2. opsi host: give TFTP back to the opsi container. 
    /opt/imaging-pxe/install-pxe.sh rollback
    It stops dnsmasq, sets OPSICONFD_PORT_UDP=69 in /opt/opsi-server/opsi-server.env, recreates the opsi container, copies snponly.efi and the .ipxe files back into its /tftpboot, and prints the first line of default.ipxe as a check. opsiconfd takes about 30 seconds to answer again.
  3. Laptop: power it fully off, then network-boot. It shows the iPXE text, then the form.

Step 1 alone is often enough: with 66/67 back, laptops take snponly.efi from the MikroTik's answer, and dnsmasq on the host still serves that file. Do step 2 when dnsmasq itself is the problem.

To go forward again later: /opt/imaging-pxe/install-pxe.sh cutover, then on the MikroTik /ip dhcp-server network set 0 next-server=0.0.0.0 boot-file-name="" and /ip dhcp-server option sets set opsi options="".

3. Revert the VM snapshot

A Proxmox snapshot of the opsi VM was taken on 9 November 2026 (evening, Central) right before the TFTP cutover. Reverting it puts the VM back to: kiosk with single-use choices and imaging reports, the Windows postinst changes, the new Ubuntu seed, dnsmasq installed but not running, and TFTP inside the opsi container.

  1. Proxmox: shut the opsi VM down, roll back to the snapshot, start it.
  2. MikroTik: put options 66/67 back (section 1, step 1). The VM after the revert serves TFTP from the container again, and nothing answers proxy DHCP.
  3. Check: podman exec opsi-server_opsi-server_1 ls /tftpboot lists snponly.efi and default.ipxe. If not, copy them in from /srv/tftp with podman cp.

Lost by the revert: imaging reports in /var/lib/imaging-kiosk/reports, choice files, and Ubuntu recovery keys filed after the snapshot. Copy /var/lib/imaging-kiosk/reports and /opt/imaging-private/recovery off the VM first if it still runs.

Everything that runs is in git, except secrets and large vendor files. Rebuild in this order on an Ubuntu 24.04 VM with two NICs (management, and ens19 on 192.168.26.0/24 as 192.168.26.106).

Order

  1. opsi stack: copy opsi-server/ to /opt/opsi-server, restore opsi-server.env, run create-secrets.sh, enable opsi-stack.service. Restore the depot (or reinstall win11-x64) and copy windows/ and postinst/active/ into it. Put the depot secrets back with the sync-*.sh scripts.
  2. Auto-enroll: install pxe-auto-enroll.py and its unit, start it, check http://192.168.26.106:8080/opsi/opsi-linux-bootimage/kernel.x64 answers.
  3. Kiosk: copy kiosk/ to /opt/imaging-kiosk, restore /opt/imaging-private, install the units, start imaging-kiosk. Check http://192.168.26.106:8091/grub.cfg?mac=02:00:00:00:00:01 returns "Loading Nextlink Imaging".
  4. Ubuntu files: ISO, NFS export, linuximage-http.service (port 8090), then build-seed-cpio.sh.
  5. Boot: /opt/imaging-pxe/install-pxe.sh stage, then cutover. Copy the WinPE build into /srv/tftp/boot when there is one.
  6. MikroTik: leave options 66/67 off (section 1 shows how to put them back if you want the old path).
  7. Test: image one Windows laptop and check its report in /var/lib/imaging-kiosk/reports.

MikroTik backups

Before the 10 November change, WinBox Files → Backup (before-pxe-20261109.backup) and /export file=before-pxe-20261109 (.rsc). Restoring the .backup replaces the whole router config and reboots it; use the two DHCP commands in section 1 instead unless the router config itself is damaged. Keep both files off the router.
