Imaging topology

How a laptop is imaged today. The bench steps are the imaging SOP; undo and rebuild steps are in imaging recovery. The 2 November plan map is kept at imaging-topology-plan-2026-11-02.html. Update this page when the path changes.

1. Network boot

RunningLaptopUEFI network boot on the imaging VLAN. Power and the cable stay connected. Secure Boot may be on or off.
→
RunningMikroTik DHCPIT-Foghat-RTR, server FoghatDHCP, hands out the address only. Options 66/67 were removed on 10 November.
→
Runningdnsmasq on .106imaging-pxe.service. Proxy DHCP picks the boot file per laptop and serves it over TFTP from /srv/tftp.
→
Runningshim → GRUBUbuntu's signed shimx64.efi (Microsoft 2011 and 2023 signatures) loads signed GRUB, which asks :8091/grub.cfg what this laptop should do.

GRUB gets one of four answers: the form (no saved choice), the Ubuntu installer, the opsi Windows path, or "boot the disk" (this Start already installed). A laptop on the WinPE test list skips shim and gets Microsoft's boot manager straight from dnsmasq. The old iPXE files (snponly.efi, default.ipxe) are still served for the opsi Windows path.

Lenovo laptops with Secure Boot on need "Allow Microsoft 3rd Party UEFI CA" turned on in the BIOS, or the firmware refuses shim.

2. The form, or the saved choice

RunningKioskSmall Linux image with a framebuffer form. Kernel is the signed Ubuntu casper vmlinuz.
→
RunningLook upThe imaging host calls nextdesk.nxlink.com with the ImagingRead app login.
→
RunningChoice file/var/lib/imaging-kiosk/decisions/<mac>.json: ticket, person, department, OS, checked apps, and which Windows path. One install boot per Start, then network boots go to the disk. Expires after 6 hours.
→
RunningOne network bootStart sets EFI BootNext to the network entry and reboots. That boot claims the choice.

The checks follow one rule. A previous laptop with a software list in NextDesk wins. With no list on that laptop, the department pack is checked. With no pack for that department name, the core apps are checked. The form says which rule it used.

3. Install

Windows 11 · opsi path (default)

RunningGRUB → iPXEHands over to snponly.efi and windows.ipxe. Unsigned, so Secure Boot must be off for this path.
→
RunningAuto-enroll :8080Creates the opsi client NL-<serial> and arms win11-x64 only.
→
Runningopsi bootimage → WinPEopsiconfd 4.3.59.4 (TCP 4447). Copies WinPE to a 10 GB partition, which 95_winpe_cleanup deletes later.
→
RunningPostinstWait screen, Wi-Fi, Entra join, apps, agents, report, handoff (section 4).

Windows 11 · WinPE path (Secure Boot on)

Waiting on WinPE buildMicrosoft boot manager2023-signed bootmgfw.efi, BCD, and boot.wim in /srv/tftp/boot, built with windows/winpe/build-winpe.ps1.
→
Waiting on WinPE buildwinpe-install.ps1Gets this laptop's answer file from :8091/api/winpe (claims the Start), partitions the disk, applies Windows 11 Pro from :8090/windows, adds drivers, unpacks postinst, runs bcdboot /bootex.
→
Waiting on WinPE buildSame postinstFrom there it is the same as the opsi path. No opsi bootimage, no 10 GB partition.

A laptop takes the WinPE path when its MAC is in /var/lib/imaging-kiosk/winpe-macs, or every laptop with KIOSK_WINDOWS_PATH=winpe.

Ubuntu 26.04 · built, not proven

Next imageInstallerSigned casper kernel via GRUB, live system over NFS, autoinstall seed appended to initrd.auto (rebuilt from git by build-seed-cpio.sh). Needs Secure Boot on.
→
Next imageLate installSaves the checked apps while the cable works. The installer encrypts the whole disk with the TPM. Firewall denies inbound. SSH, Avahi, rpcbind, and wsdd are off. Entra uses the public UbuntuOauth client. NVIDIA through ubuntu-drivers.
→
Next imageFirst bootimaging-firstboot.service files the disk recovery key and sends the imaging report. No disk password; the employee signs in with Entra.

4. Windows postinst, after the operating system is on disk

The runner (windows/postinst.cmd, depot win11-x64/opsi/postinst.cmd) runs every .cmd and .ps1 in postinst.d in name order, cancels any pending reboot before each step, and tells the imaging host when each step starts and ends. The imaging cable stays connected until handoff.

PieceRole
00, 01, 02Wait screen with the person's name, the install-running marker and no-auto-reboot policies, firewall on.
03_force_dhcp.cmdResets the network card only when the laptop cannot reach the imaging host or the internet.
03b_fetch_kiosk_apps.cmdSaves the checked software from the imaging host before Wi-Fi can move the laptop off that network.
04, 05, 06, 10Joins Nextlink_Corp, hides the account and privacy questions, Windows Hello PIN policy, Entra bulk join.
50_debloatRemoves consumer Store apps. 50_opsi-client-agent.cmd and 80_repartition.cmd do nothing on purpose; they replace the product's stock files of the same name.
60, 61, 62Atera, Wazuh, and UniFi Endpoint on every image.
70_core_apps.cmdChecked catalog apps, from the imaging host's app cache when cached (section 6). A cached installer that fails is retried once through winget. A stuck installer is skipped after 3 minutes with no activity.
71, 75OneDrive preferences and the start menu.
95, 96Removes the opsi WinPE partition and any opsi agent files.
98_imaging_report.cmdUploads the logs and posts the report (serial, model, person, Entra, Secure Boot, TPM, BitLocker, failed apps, missing agents) to the imaging host.
99_handoff.cmdHides NextAdmin, clears autologon, sets Welcome plus the employee name, registers LabIdleWindowsUpdate, deletes the answer file, and reboots once to the work sign-in.
LabIdleWindowsUpdateAfter that reboot, installs Windows updates and drivers at the sign-in screen, restarts only while nobody is signed in, stops after 5 passes or once someone signs in, and sends the result for a second ticket note.

Department apps are not installed by a login task. WiFiman, when checked, is scheduled for the employee’s next sign-in because it does not install as the machine account. WSL turns the feature on now and finishes the distro after a reboot.

5. Where it lives

Imaging host192.168.26.106 (opsi VM). Kiosk API on 8091 (imaging-kiosk.service, /opt/imaging-kiosk), files on 8090 (linuximage-http.service, /opt/linuximage), auto-enroll on 8080, opsiconfd on 4447. Ports 8090 and 8091 listen only on the imaging address.

Choices and boot tags/var/lib/imaging-kiosk/decisions (one JSON per MAC, colons removed; delete it to show the form again) and /var/lib/imaging-kiosk/pxe-tags (WinPE laptops). Not served on 8090.
Reports and logs/var/lib/imaging-kiosk/reports: every report (<time>-<serial>.json) and log bundle (-logs.zip). Live: journalctl -u imaging-kiosk -f.
Private files/opt/imaging-private, root-only. NextPass token, Atera link, Wazuh password, UniFi package, NextAdmin and Ubuntu install passwords, Ubuntu disk recovery keys (recovery/<mac>.pass). An Ubuntu Start lets that laptop read the Wazuh password and the Atera link once each.

Ubuntu recovery and lockdown

The installer’s TPM disk encryption makes the recovery key. On first boot the laptop posts it to the imaging host, which keeps one key per MAC and emails a NextPass link to the imaging owner. The link expires after 90 days or 5 views. The host file remains until a vault exists. Imaging that MAC again deletes the old key.

The same install denies new inbound connections and allows outbound. SSH, Avahi, rpcbind, and Windows discovery are off. Name resolution, time sync, and printing stay installed, and inbound traffic to them is dropped. Automatic security updates are on. Hibernate and hybrid sleep are masked.

6. Speed and visibility

Apps install from the imaging host over the cable. app-cache-sync.timer refreshes /opt/linuximage/apps every night at 04:30: direct installers as they are, winget apps from Microsoft's winget manifests with winget's own silent switches and SHA-256 check. MobaXterm, WiFiman, and WSL still come from the internet. A cached installer that fails is retried once through winget.

The postinst runner tells the host when each step starts and ends (journalctl -u imaging-kiosk | grep progress shows it live). The report on the ticket lists the slowest steps and the total. The report step uploads the laptop's C:\opsi.org\log, progress folder, and Panther setup logs to /var/lib/imaging-kiosk/reports. 03_force_dhcp.cmd resets the network card only when the laptop is really offline.

Windows Update is not part of imaging any more. Handoff registers LabIdleWindowsUpdate, which installs updates and drivers at the sign-in screen after the handoff restart, restarts again only while nobody is signed in, stops after 5 passes or when someone signs in, and writes the result as a second note on the ticket. Its log is C:\opsi.org\log\windows_update_idle.log.

If imaging stops working, the undo steps and the host rebuild are in imaging recovery.

Open

  • No laptop has been imaged since the 10 November changes. The first images check the signed boot path, the single handoff reboot, the app cache, and the step timing.
  • The WinPE path waits on a 2023-signed WinPE build (windows/winpe/README.md).
  • Ubuntu with TPM full-disk encryption has not finished on a laptop. Older Ubuntu releases had autoinstall bugs with it.
  • Imaging reports and the Windows Update follow-up cannot be written on NextDesk tickets until NextDesk has an ImagingWrite app role (brain todo #1125). They are kept on the host until then.
  • Secrets exist only on the VM and its snapshot. Copy them into the vault (list in imaging recovery).
  • UniFi VPN and the NextDesk endpoint are locked on the form and have no package.
  • The opsi client agent is not installed. Identity, software inventory, and bookmark backup were agent products, so they do not run.
  • The USB sticks are the old seed. A dock does not set the BIOS. The new-hire group is still added by hand.
