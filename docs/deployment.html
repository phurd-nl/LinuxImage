The boot screen

A laptop on the imaging VLAN does not load GRUB. DHCP on that VLAN hands out snponly.efi, the FOG iPXE file. That choice is already made, and it is not stored on this host. It was made so a Lenovo L15 Gen 3, and other picky UEFI firmware, can PXE-boot. iPXE runs default.ipxe, which now shows a menu and waits until someone chooses. Nothing starts on its own. Windows chainloads windows.ipxe, the previous auto-enroll script, unchanged. Ubuntu starts only when someone presses U. Secure Boot is usually fine with this boot file.

The graphical menu is on the depot and nothing loads it. grub.x64.efi draws gfxterm at 1280×720. The theme and the background picture are packed inside that EFI file. The shared grub.cfg waits 3 seconds. The first entry is the local disk when an operating system is already installed. The other entry starts the opsi boot image with no client and no product, so it is not the Windows installer the VLAN uses now. grub-shim.x64.efi is the Secure Boot copy of that loader. opsipxeconfd also writes one file per armed MAC. Those files wait 0 seconds and contain a single Windows entry. A laptop that has one would skip the picture and start Windows.

How a choice gets on screen

The menu is GRUB, in two configs, drawn in the imaging topology. DHCP stays on snponly.efi so a picky UEFI machine can still start the network boot. default.ipxe does not ask. Its only job is to chainload grub.x64.efi.

grub.cfg is the graphical menu. It tries the font and gfxterm at 1280×720, then 1024×768, then auto. The theme and the background stay inside the EFI file. The menu waits for a key. The same file loads grub-simple.cfg when the font will not load or gfxterm refuses to start. Esc loads that simple menu too, including when the panel stays black and gfxterm still reported success. Keyboard input stays on the console the whole time.

grub-simple.cfg is the other menu. Text only. No theme, no picture, no timeout, and no local-disk default. The choices match the graphical menu, so a tech learns one list.

  • Sign in to image. Later this boots the Entra console. Until that console exists, the row can stay off the menu.
  • Install Windows 11. This chainloads a second iPXE file whose script is only the current auto-enroll URL. It must not return to default.ipxe, or the laptop loads GRUB again.
  • Install Ubuntu 26.04. Visible, and it returns to the same menu until gate 2. A timeout must not select it.
  • Boot the disk already in this laptop. GRUB chainloads the local EFI file. Nothing is enrolled.
  • Simple menu, on Esc. Opens grub-simple.cfg.

If grub.x64.efi itself fails to start, the simple GRUB menu never runs, because it is the same binary. default.ipxe then shows the same choices as text. That last resort is only for firmware that rejects the EFI, which is the Lenovo L15 case we already hit. One L15 still has to prove the chainload before this becomes the VLAN default.

A per-client file with timeout 0 must not be the file GRUB opens first. Those files skip both menus and start Windows. The embedded loader looks for a MAC file before grub.cfg.

What happens after Deploy

Deploy writes one selection file on the depot, named by the laptop’s MAC address. Then it chainloads the installer. The tech can leave. The file holds the operating system, the employee’s account name, the software to install during imaging, and the software queued for after that person signs in. Both installers read that same file. The list comes from the NextDesk ticket: the employee on the ticket, that person’s department, and the department software already on the depot. UniFi VPN is on every laptop. The NextDesk endpoint package is present in the plan and stays turned off. Deploy does not run without a resolved ticket.

  1. Windows 11

    The existing opsi win11-x64 netboot product installs Windows from the stock ISO already on the depot. The selection file becomes the opsi product actions for that client, so the checked applications install during the normal post-install. No new Windows imaging engine, and no BitLocker step.

  2. Ubuntu 26.04

    After the boot screen is in front of the tech, the Ubuntu item loads the current desktop ISO with the NoCloud seed served by the depot: 

    autoinstall ds=nocloud;s=http://192.168.26.106:8090/nocloud/

    This is our seed, not the stock opsi ubuntu26-04 product, and not the paid opsi Linux agent. The opsi host is where the ISO and the seed live. One Ubuntu entry is on the menu, and it is 26.04 LTS. A depot job replaces the ISO when Ubuntu publishes a new 26.04 image and replaces the seed when we rebuild it. The menu does not ask the tech to pick a version. Security updates install from the Ubuntu archive during that install. They do not become a new ISO. A USB holds the same files and is used only when a laptop cannot reach the host. The late-commands on disk today still read only /cdrom. The seed change fetches from the host first and uses the USB when that URL is missing.

  3. No second tech prompt

    Disk layout, packages, firewall, encryption, Timeshift, Entra broker, hidden local admin, dock, and the checked apps are applied by the installer and the first boot. The target wizard does not ask the tech for a password. The scripts that exist today still stop and ask. The recovery passphrase is generated and stored with the selection record, not in the image.

The employee still signs in once, after imaging, with their own Entra account. The tech’s token cannot become that person’s laptop login or their OneDrive token. That sign-in is theirs. It is not part of the imaging session.

First boot, with nobody at the keyboard

  1. Apply the BIOS update in BIOS, including its reboot, and record that it finished.
  2. Create the home partition in the free space and format LUKS2.
  3. Copy the install account’s home into the volume, add the recovery and admin slots, and seal the TPM key.
  4. Reboot, confirm /home is /dev/mapper/home_crypt, reseal to PCR 7 only, and delete the plaintext copy.
  5. Point Timeshift at the encrypted home. Keep two daily snapshots. The timer does nothing while the volume is locked.
  6. Hide the local admin from the greeter and turn off the user list, so the screen asks for a name.
  7. Install the Entra broker with device registration on, allowed_users = ALL, and an empty owner. The employee is in the new-hire group for one day, and their sign-in joins the device. Any account the app accepts can sign in after that. A client secret is not stored on the laptop.

Full-disk TPM encryption is not the plan. It unlocks the whole disk at boot and leaves it open at the lock screen, and it only auto-unlocks when the OEM fused Intel Boot Guard or AMD Platform Secure Boot. Encrypted home locks the person’s files at logout on every laptop we buy. Suspend-to-RAM stays available. Hibernate, hybrid-sleep, and suspend-then-hibernate stay masked: each one writes memory into swap, and this swap is activated only after sign-in, from inside the encrypted home, so the laptop could not wake. The script on disk today masks sleep.target as well. The image change unmasks sleep.target and suspend.target and leaves those three disk modes masked. Lid close and idle use suspend. While the laptop is suspended the disk key stays in RAM, the same as a locked screen, until the battery dies.

BIOS, before the disk is sealed

Dell and Lenovo laptops get the current vendor BIOS during imaging, on AC power, before the wizard seals the TPM. The first seal uses PCRs 0, 2, 4, and 7. A BIOS flash changes PCR 0, so a flash after that seal and before the PCR 7 reseal makes the TPM withhold the key. After the reseal, a later BIOS update is safe. A UEFI dbx update still moves PCR 7, so this step does not apply dbx updates.

One reboot applies the flash. A marker stops the step from running again. No package means the model is recorded and imaging continues.

Windows image

Windows stays on win11-x64. The product and setup.exe are on the depot, about 8.6 GB. The new work is the front door and the selection file, not a second Windows installer. Checked rows that match opsi products are set to install for that client before the boot image hands off. A laptop that opsi has never inventoried has an empty checklist. The tech can still pick the OS and deploy.

The PXE menu waits until someone chooses. Windows chainloads windows.ipxe. That script calls http://192.168.26.106:8080/ipxe/auto.ipxe, creates a client named NL-<serial>, and arms win11-x64 setup. Specialize still creates NextAdmin, joins Nextlink_Corp, and leaves AutoLogon off. The employee joins Entra in work OOBE. First logon runs debloat, Start pins, and Atera. At the finished greeter the person types user@domain. Signing in by typing the Entra password makes that password the local password too. New hire, for one day

Entra device settings allow only the new-hire security group to join a device. The group is not named linux- anything, so authd does not turn it into a local group. When the laptop is assigned, that employee is added to the group. Their sign-in is what joins the device. Twenty-four hours after the add, the membership ends. That does not unjoin the laptop and does not sign them out. It stops them joining another device.

The end time is set on the group assignment. A daily job is the fallback: remove anyone whose add time is older than a day. The laptop script cannot change this group.

Sudo for an Entra account

An Entra sign-in does not get sudo. setup-entra-authd.sh sets allowed_users to ALL and owner to empty, so the imaging login that registers the device does not lock everyone else out. It does not set extra_groups or owner_extra_groups. The hidden local admin stays a normal UNIX account, so its sudo is still /etc/group.

For the fleet, an Entra group named exactly linux-sudo maps onto the local sudo group. Add or remove the person there. authd learns that on the next online sign-in. The desktop session they are already in keeps the old group list. authctl cannot pull a new group list. An Entra group named sudo, without the linux- prefix, can make login fail because the local group already exists. A local usermod is rewritten on the next online sign-in.

To give or take the sudo command without a sign-out, use a file in /etc/sudoers.d/. The name is the full Entra address, quoted because of the @. Write it with visudo -f and mode 0440. 

"name@domain.com" ALL=(ALL:ALL) ALL

Delete that file to remove sudo. Also delete their ticket under /run/sudo/ts/ so an approval from the last few minutes cannot still be used. authd will not undo this file, because it is not a group. The next sudo command sees the change. The desktop admin prompts still use the groups captured at login, so those prompts change only after they sign in again.

Apps, dock, and OneDrive

These are installed from the selection file during imaging, before the employee sits down. They are not in the seed today.

  • The dock sits at the bottom, short and centered, from a system dconf default. It is not on the left.
  • Teams opens https://teams.microsoft.com as an app window. Outlook opens https://outlook.office.com. Both are pinned.
  • The OneDrive package is installed with the public client id only. The sync token is created when that employee signs in. A client secret is not copied onto the laptop.
  • Anything the checklist leaves unchecked is not installed.

  2. Gate 1. The 26.04 LTS ISO on the host, then one spare laptop

    Grow ubuntu-lv before copying the ISO. The volume is 48 GB with 4.8 GB free, and the volume group has 49 GB unallocated. Keep the files on the host, outside the opsi container, for example /opt/linuximage/. Listen on 192.168.26.106 on a new port. Leave ports 69, 4447, and 8080, and the container depot, alone.     Change the late-commands so they download the tarball and late-install-linux-encryption.sh from that host URL, and use /cdrom only when the URL is missing. Do not edit default.ipxe in this gate.

    Use a spare laptop with TPM 2.0 and enough disk that a 40 GB root leaves at least 50 GB free at the end. Cable it. The seed has no Wi-Fi. The imaging LAN can reach the Ubuntu archive: a fetch from ens19 on the depot returned HTTP 200. Turn Secure Boot on before this boot.     The install account is user. Rename it before the wizard, not after. At the wizard, mark the temporary password, type the password from TECH-PASSWORD.txt, and set the new one. That new password is LUKS slot 0. Slot 1 is the recovery passphrase. Slot 2 is the TPM key, sealed first to PCRs 0, 2, 4, and 7, then resealed to PCR 7. Write the recovery passphrase down and shred the copy on the laptop.

    This gate passes when a reboot shows /home on /dev/mapper/home_crypt and the account can log in. Leave ENTRA_TENANT_ID and ENTRA_CLIENT_ID unset, so the broker is not configured.

  3. Gate 2. A USB backup of those same files

    Write one USB from the ISO and nocloud/ directory the host is already serving, including nocloud/extras/. Keep that stick. Boot it only when a laptop cannot reach the host. The kernel argument is then autoinstall ds=nocloud;s=/cdrom/nocloud/. The next laptop still boots from the host.

  4. Gate 3. A choice on the PXE menu

The file adds product actions. It does not replace the product. Do not set opsi-linux-client-agent to setup.
