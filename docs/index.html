Ubuntu fleet encryption

Golden images that encrypt /home on first boot

LinuxImage is LUKS2 + TPM auto-unlock tooling for Ubuntu laptops: bake a wizard into the image, users enter their login password once, and encryption, sealing, and cleanup run unattended.

  • TPM 2.0 · PCR 7
  • First-boot password box
  • Self-heal after SB drift

What you get

Encrypted home, not full-disk drama

Only /home is LUKS2. Root stays simple for imaging; user data is encrypted at rest after logout.

TPM auto-unlock at login

A random key is sealed with Clevis to the TPM. Login opens the volume; logout closes it. No plaintext keyfile on disk.

Mandatory first-boot wizard

Fullscreen Ubuntu-styled password box. User types their login password; partition, encrypt, seal, harden, and purge run automatically.

Fleet / golden-image ready

Leave ≥50 GB free at the end of the boot disk. Autoinstall seed + late-install hook drop the wizard into every clone.

Firmware-update resilient

After setup, the seal is PCR 7 only (Secure Boot state). BIOS updates no longer brick auto-unlock; self-heal covers rare PCR drift.

Offline recovery floor

Separate recovery passphrase (keyslot 1). Wizard stores it root-only until admins collect it—or push to Ansible.

How first boot works

  1. 1

    Image boots with free space

    Wizard service listens on loopback. Kiosk relaunches until encryption is complete.

  2. 2

    User enters Ubuntu login password

    Verified via PAM. Becomes LUKS keyslot 0 (kept in sync on password change).

  3. 3

    Partition · encrypt · migrate · seal

    Creates the home partition, LUKS2 format, rsync of /home, TPM-sealed key, PAM open/close hooks.

  4. 4

    Reboot · verify · harden · purge

    Confirms auto-unlock, re-seals to PCR 7 + self-heal, then irreversibly wipes the plaintext shadow on root.

Security model

Destructive by design

These scripts reformat a partition and later wipe plaintext /home. Never run them on a machine that isn’t the intended target. Read RUNBOOK.md first.

Guards built in

  • Refuse to format devices that already have a signature
  • Purge only if live /home is the encrypted mapper
  • Fail-closed after purge (PAM required if unlock fails)
  • Credentials only on tmpfs; shredded on every orchestrator exit
  • Wizard API: loopback-only, origin check, rate-limited starts
  • No skip via user cache file until root marks complete

Quick start

Safe to build on a dev machine. Only deploy / encrypt on a target VM or laptop.

# Clone
git clone https://github.com/phurd-nl/LinuxImage.git
cd LinuxImage

# Validate + tarball (safe on dev)
bash scripts/build.sh

# On a target / golden-image VM (root)
sudo bash scripts/deploy.sh
# or full image prep:
sudo bash scripts/prepare-ubuntu-image.sh

# Capture the image with ≥50 GB unallocated at end of boot disk.
# First boot: user enters login password in the LUKS box — rest is automatic.

Before you touch disks

  1. Edit scripts/config.sh (DISK, PARTNUM, USERNAME, MAPPER).
  2. Run bash scripts/test-config.sh.
  3. Enable Secure Boot (PCR 7 depends on it).
  4. Follow numbered scripts in order — or let the wizard orchestrate them.
